# 사용방법 및 기존 프로젝트 통합 안내 — 스팀 앱 번호로 게임 장르·태그 조회

## 1. 작업물 개요

스팀 앱 번호(예: 엘든 링 = `1245620`)를 주면 **그 게임의 장르(`genres`)와 태그(`tags`)** 를 돌려주는 API `GET /api/games/by-steam/{app_id}` 를 추가한 작업물입니다.
추천 가중치 점수를 계산하려면 게임마다 어떤 태그가 붙어 있는지 알아야 하는데, 지금까지는 스팀 번호로 그것을 받아오는 기능이 없었습니다.

- RAWG 와 IGDB 가 같은 뜻을 다르게 부르는 이름은 **하나로 통일**합니다 (예: IGDB `Co-operative` = RAWG `Co-op`, `Platform` = `Platformer`, `Open world` = `Open World`).
- 스팀 기능 표시(`Steam Achievements`, `Full controller support` 등)는 취향과 무관해서 **뺍니다**.
- **DB 에는 쓰지 않는 읽기 전용 API** 입니다. `sql/` 변경도 없습니다.

**독립 실행 가능한 전체 프로젝트가 아닙니다.** 기존 프로젝트(`기존프로젝트/`) 위에 변경 파일을 반영해서 사용합니다.

## 2. 폴더 및 파일 구성

작업물 폴더 안의 경로는 `기존프로젝트/` 루트를 기준으로 한 상대경로를 유지합니다.

### 변경된 파일 8개 (새 파일 2개 포함)

**백엔드**
- `app/routers/games.py`: 새 API `GET /api/games/by-steam/{app_id}` 추가
- `app/services/game_tags.py` **(새 파일)**: DB → RAWG·IGDB 실시간 조회 → 스팀 순서로 태그를 모아 통일
- `app/services/steam.py`: 스팀 상점의 영문 장르·카테고리를 받는 `fetch_app_labels()` 추가
- `app/services/game_clean.py`: 스팀 영문 이름·`Open World` 표기를 통일하는 표 몇 줄과, 취향과 무관한 기능 표시 4개 추가
- `app/docs.py`: Swagger 한국어 설명 추가 (`games_by_steam`)

**테스트**
- `tests/test_api_game_tags.py` **(새 파일)**: 새 API 테스트 12개 (가짜 DB·가짜 외부 응답, 키·인터넷 불필요)
- `tests/test_api_docs.py`, `tests/test_docs_coverage.py`: API 개수 검사를 25개 → 26개로 수정

**문서**
- `사용방법.md`, `변경내용_비교보고서.md`

## 3. 적용 방법

1. `기존프로젝트/` 에서 먼저 현재 상태를 확인합니다 (`python -m pytest` 가 통과해야 합니다).
2. 이 폴더의 `app/`, `tests/` 안 파일을 **같은 경로**로 복사합니다. 새 파일 2개는 그냥 추가되고, 나머지 6개는 기존 파일을 덮어씁니다.
3. **`app/docs.py`, `app/services/steam.py`, `app/services/game_clean.py`, `app/routers/games.py` 는 다른 작업물에서도 고칠 수 있는 공용 파일**입니다. 통째로 덮어쓰지 말고, 바뀐 곳만 반영하려면 `변경내용_비교보고서.md` 의 "공용 파일에서 바뀐 곳" 을 보세요.
4. 반영 후 `python -m pytest` 로 확인합니다 (기대 결과: **106개 통과**, 이 작업물을 반영한 상태 기준).

## 4. 환경변수

새로 추가한 환경변수는 **없습니다.** 기존 `.env` 의 아래 값을 그대로 씁니다 (값은 저장소에 올리지 않습니다).

| 이름 | 없으면 |
|---|---|
| `RAWG_API_KEY` | RAWG 조회를 건너뜁니다 |
| `IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET` | IGDB 조회를 건너뜁니다 |

둘 다 없어도 API 는 동작하고, 그 경우 스팀 장르·카테고리만 돌려줍니다. 키 발급 방법은 `기존프로젝트/README.md` 의 7단계를 보세요.

## 5. 실행 및 확인

```powershell
cd 기존프로젝트
.\.venv\Scripts\Activate.ps1
fastapi dev app/main.py
```

브라우저에서 http://localhost:8000/docs → `games (게임 목록)` 에서 **Get Game Tags by Steam ID** 를 펼쳐 `app_id` 에 `1245620` 을 넣고 Execute 합니다.
주소로 바로 확인하려면 http://localhost:8000/api/games/by-steam/1245620 을 엽니다.

### 응답 예 (실제 IGDB·스팀 조회 결과의 일부)

```json
{
  "steam_app_id": 1245620,
  "game_id": null,
  "title": "ELDEN RING",
  "genres": ["Action", "RPG", "Adventure"],
  "tags": ["Singleplayer", "Multiplayer", "Co-op", "Fantasy", "Open World", "Third Person"],
  "source": "live",
  "sources": ["igdb", "steam"]
}
```

게임마다 다른 태그가 나옵니다. 예를 들어 스타듀 밸리는 `Sandbox`, `Romance`, `Business`, 도타 2는 `MOBA`, `Warfare` 가 붙습니다.

### `source` 값의 뜻

| 값 | 뜻 |
|---|---|
| `db` | DB(`games`) 에 저장된 RAWG/IGDB 수집 결과를 사용 |
| `live` | DB 에 게임이 없거나 태그가 비어 있어서 RAWG·IGDB 를 **방금 조회**하고 스팀 값과 합침 (결과는 6시간 서버 메모리에 보관) |
| `steam` | RAWG·IGDB 키가 없거나 둘 다 실패해서 스팀 값만 사용 |

`sources` 에는 실제로 합친 곳이 나옵니다 (예: `["rawg", "igdb", "steam"]`).

### 오류 응답

| 상황 | 응답 |
|---|---|
| 스팀도 모르는 번호 | 404 `{"error": "게임을 찾을 수 없습니다. 스팀 앱 번호를 확인해 주세요."}` |
| 번호가 숫자가 아니거나 0 이하 | 422 |
| 스팀 상점이 응답하지 않음 | 502 (키가 응답·로그에 노출되지 않음) |

RAWG·IGDB 한쪽이 실패해도 오류로 만들지 않고, 나머지 값으로 계속 돌려줍니다.

## 6. 같은 게임인지 확인하는 방법 (잘못된 게임이 섞이지 않게)

- **RAWG**: 후보 중 스팀 상점 번호가 일치하는 게임을 우선 사용합니다. 번호로 대조할 수 없으면 **이름이 정확히 같은 게임만** 씁니다.
- **IGDB**: 이름이 정확히 같은 결과만 씁니다.
- 평가·추가 수가 거의 없는 비공식 RAWG 항목은 제외합니다 (기존 수집 규칙과 같음).

## 7. 알아둘 점 · 한계

- **RAWG 실제 호출은 확인하지 못했습니다.** 확인하던 시점에 `api.rawg.io` 서버가 오류 522(응답 없음)였습니다. RAWG 경로는 가짜 응답 테스트까지만 통과했고, 복구된 뒤 한 번 더 확인이 필요합니다. IGDB 는 실제 호출로 확인했습니다 (엘든 링·스타듀 밸리·할로우 나이트·도타 2).
- IGDB 태그는 RAWG 보다 굵직합니다 (예: 할로우 나이트에 `Atmospheric`, `Difficult` 같은 세부 태그 없음). RAWG 가 되면 더 풍부해집니다.
- 스팀 상점의 접근성 항목이 태그에 남을 수 있습니다 (`Camera Comfort`, `Custom Volume Controls`, `Color Alternatives`, `Save Anytime`, `Playable without Timed Input`). 추천에 불필요하면 `game_clean.py` 의 `TAG_STOPLIST` 에 넣으면 빠집니다.
- `PvP` 와 `Online PvP`, `Co-op` 와 `Online Co-op` 는 별개 태그로 남습니다. 하나로 합칠지 팀에서 정해 주세요.
- 스팀 상점의 **사용자 태그**(로그라이크 등)는 공식 API 에 없어서 포함하지 않습니다.
- 태그 이름은 **원문(영어)** 입니다. 추천 가중치가 `tag:open_world` 같은 코드를 쓴다면 변환이 필요하고, 코드 목록을 받으면 붙일 수 있습니다.
- DB 에 게임이 있으면 DB 값을 먼저 씁니다. 실제 DB 에 게임을 채우는 일(`/api/admin/games/sync`)은 이 작업물에 포함되지 않았고, DB 담당과 합의가 필요합니다.
- 실시간 조회는 게임 하나에 RAWG 최대 5회·IGDB 1회 호출이 들어갑니다. 같은 번호는 6시간 동안 서버 메모리의 결과를 다시 씁니다.
