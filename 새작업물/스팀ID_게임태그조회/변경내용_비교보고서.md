# 변경 내용 비교 보고서 — 스팀 앱 번호로 게임 장르·태그 조회

비교 대상은 `main` 의 `기존프로젝트/` (커밋 `c9dface`, 2026-11-04)와 이 작업물을 반영한 상태입니다.
**기존 코드는 한 줄도 지우거나 바꾸지 않았고, 추가만 했습니다** (아래 "공용 파일에서 바뀐 곳" 참고).

# PART 1. 배경과 변경 요약

## 문제
추천 가중치 점수를 계산하려면 **게임마다 어떤 태그(예: 협동, 오픈월드)가 붙어 있는지** 알아야 합니다. 그런데 스팀 앱 번호로 게임의 장르·태그를 받아오는 기능이 없었습니다.
- RAWG·IGDB 태그를 가져와 DB(`games.tags`)에 저장하는 코드는 있었지만, **스팀 번호로 조회하는 통로**가 없었습니다.
- 스팀 `appdetails` 는 장르와 카테고리(싱글·협동 등)만 주고, "오픈월드" 같은 사용자 태그는 주지 않습니다. 그래서 이런 태그는 RAWG·IGDB 쪽에서 가져와야 합니다.

## 변경
| 구분 | 내용 |
|---|---|
| 새 API | `GET /api/games/by-steam/{app_id}` (읽기 전용, DB 쓰기 없음) |
| 조회 순서 | 1) DB 에 저장된 값 → 2) 없거나 비어 있으면 RAWG·IGDB 를 그때그때 조회하고 스팀 값과 합침 → 3) 키가 없거나 실패하면 스팀 값만 |
| 이름 통일 | 기존 `game_clean.normalize()` 를 그대로 재사용 + 스팀 영문 이름·`Open World` 표기 몇 줄 추가 |
| 안전장치 | RAWG·IGDB 는 스팀 번호 또는 정확히 같은 이름으로 찾은 게임만 사용, 한쪽 실패는 건너뜀, 로그·응답에 키 미노출 |
| 캐시 | 실시간 조회 결과를 서버 메모리에 6시간 보관 (기존 `market.cached` 재사용) |

## 확인한 결과
- `python -m pytest`: 이 작업물을 반영한 상태에서 **106개 통과** (기존 94개 + 새 12개). 단독 로직 테스트 7개 모듈도 통과.
- **IGDB 실제 호출 확인**: 엘든 링, 스타듀 밸리, 할로우 나이트, 도타 2 를 조회해 게임마다 다른 태그가 나오는 것을 확인했습니다.
- **RAWG 실제 호출은 확인하지 못했습니다.** 확인 시점에 `api.rawg.io` 가 오류 522(서버 응답 없음)였습니다. 가짜 응답 테스트까지만 통과했습니다.
- 서버를 켜서 Swagger 화면에서 직접 눌러 보는 확인은 하지 않았습니다.

# PART 3. 팀에서 정해 줄 것

1. 접근성 항목(`Camera Comfort`, `Custom Volume Controls`, `Color Alternatives`, `Save Anytime`, `Playable without Timed Input`)을 태그에서 뺄지.
2. `PvP` 와 `Online PvP`, `Co-op` 와 `Online Co-op` 를 하나로 합칠지.
3. 추천 가중치가 쓰는 **태그 코드 이름**(예: `tag:open_world`, `category:co_op`) 목록. 받으면 원문 태그를 그 이름으로 바꿔서 내려줄 수 있습니다.
4. 실제 DB 에 게임을 채울지(`/api/admin/games/sync`). 실제 DB 쓰기이므로 DB 담당과 합의가 필요합니다. 채워 두면 실시간 조회 없이 DB 값(`source: "db"`)으로 더 빠르게 응답합니다.
