# 사용방법

## 1. 작업물 안내

이 폴더는 RecomEngine 프로젝트의 회원가입·이메일 인증·로그인, 비회원/회원 상태 저장, 진단 결과 저장 및 시작 화면 흐름 업데이트 작업물입니다.

이 작업물은 기존 프로젝트와 분리된 검토용 코드입니다. 프로젝트에 적용할 때는 기존 파일을 백업하고 동일 경로의 파일을 비교한 뒤 필요한 변경만 반영하세요.

## 2. 실행 환경

- Python: 프로젝트의 `requirements.txt`에 명시된 패키지를 설치할 수 있는 버전
- Node.js 및 npm: 프론트엔드의 `package.json`을 지원하는 버전
- 실제 회원 인증/회원 데이터 저장: Supabase 프로젝트 설정 필요
- AI 심화 설문 생성: Ollama 및 사용할 모델이 준비된 경우 사용

## 3. 환경변수 설정

1. 백엔드 프로젝트 루트의 `.env.example`을 참고해 로컬 `.env` 파일을 만듭니다.
2. 외부 서비스 연동 없이 개발 흐름을 확인할 때는 `USE_MOCK_DB=true`로 설정할 수 있습니다. 모의 DB 데이터는 서버를 종료하면 유지되지 않습니다.
3. 실제 Supabase DB를 사용할 때는 `USE_MOCK_DB=false`로 설정하고 다음 값을 입력합니다.
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_KEY`
   - `SUPABASE_ANON_KEY`
   - `SESSION_SECRET`
4. 실제 DB 모드에서 `SESSION_SECRET`은 필수이며 16자 이상이어야 합니다. 생성 예시:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

5. HTTPS 배포에서는 `COOKIE_SECURE=true`로 설정합니다.
6. Ollama를 사용할 경우 `OLLAMA_BASE_URL`, `OLLAMA_MODEL`을 실행 환경에 맞게 설정합니다.
7. 실제 비밀값이 포함된 `.env`는 Git에 추가하지 않습니다. 저장소에는 값이 비어 있는 `.env.example`만 둡니다.

## 4. 설치 및 실행

명령은 프로젝트 루트 기준입니다.

### 백엔드

가상환경을 만들고 의존성을 설치합니다.

**Windows PowerShell**
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

**macOS / Linux**
```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

환경변수를 설정한 뒤 백엔드를 실행합니다.

```bash
uvicorn app.main:app --reload
```

기본 개발 주소는 `http://127.0.0.1:8000`입니다.

### 프론트엔드

새 터미널에서 프론트엔드 폴더로 이동해 의존성을 설치하고 개발 서버를 실행합니다.

```bash
cd frontend
npm install
npm run dev
```

터미널에 표시되는 Vite 로컬 주소로 접속합니다. API 프록시 주소가 별도로 필요한 환경에서는 `frontend/.env.example`을 참고해 프론트엔드 환경변수를 설정합니다.

## 5. 주요 기능 확인 순서

### 회원가입 및 이메일 인증
1. 시작 화면에서 회원가입을 엽니다.
2. 닉네임, 이메일, 비밀번호와 비밀번호 확인을 입력합니다.
3. 비밀번호 확인이 일치하지 않으면 제출되지 않는지 확인합니다.
4. Supabase 이메일 인증이 필요한 설정이면 인증 메일 안내가 표시되는지 확인합니다.
5. 이메일 인증을 완료한 뒤 앱으로 돌아와 회원가입을 마무리하고 이용 경험 선택 화면으로 이동하는지 확인합니다.

### 로그인 및 계정 상태
1. 기존 계정으로 로그인합니다.
2. 새로고침 후에도 세션이 유지되는지 확인합니다.
3. 회원 상태가 계정별로 불러와지는지 확인합니다.
4. 상태를 변경한 뒤 저장 상태가 반영되는지 확인합니다.
5. 로그아웃 후 계정 세션이 종료되는지 확인합니다.

### 비회원 상태 저장
1. 비회원으로 시작해 이용 경험을 선택합니다.
2. 빠른 진단을 진행하고 브라우저를 새로고침합니다.
3. 같은 브라우저에서 저장된 상태가 복원되는지 확인합니다.
4. 비회원 저장 데이터는 마지막 저장 시각 기준 7일 후 만료됩니다.

### 진단 결과 저장
1. 빠른 설문 또는 완료 가능한 진단을 진행합니다.
2. 결과 화면이 표시되는지 확인합니다.
3. API 연결 환경에서는 진단 세션 생성, 답변 저장, 완료 결과 저장 요청이 실행되는지 확인합니다.
4. 서버 저장 실패 시 결과 화면은 유지되고 저장 실패 안내가 표시되는지 확인합니다.
5. 심화 설문은 Ollama 연결 상태에 따라 AI 생성 또는 대체 문항 흐름으로 진행되는지 확인합니다.

## 6. 관련 API

**계정**
- `GET /api/account/session`
- `POST /api/account/signup`
- `POST /api/account/login`
- `POST /api/account/logout`
- `PUT /api/account/state`

**설문**
- `POST /api/survey/generate`
- `GET /api/survey/questions?track={track}&stage={stage}`

**진단 결과 저장**
- `POST /api/sessions`
- `PUT /api/sessions/{session_id}/answers`
- `POST /api/sessions/{session_id}/complete`

## 7. 테스트 및 빌드

프로젝트 루트에서 백엔드 테스트를 실행합니다.

```bash
pytest -q
```

프론트엔드 테스트와 빌드는 프론트엔드 폴더에서 실행합니다.

```bash
cd frontend
npm test
npm run build
```

각 명령의 성공 여부는 실제 실행 결과로 확인하세요. Supabase 이메일 발송, 실제 DB 쓰기, Ollama 응답은 로컬 단위 테스트만으로 검증되지 않을 수 있으므로 연동 환경에서 별도로 확인해야 합니다.

## 8. Supabase 사전 확인

실제 DB 모드로 실행하기 전에 Supabase 대시보드에서 다음을 확인합니다.

- Auth 이메일 인증 설정 및 인증 완료 후 돌아올 URL
- `user_states` 테이블과 `user_id` 기준 upsert 권한/RLS 정책
- 진단 세션·답변·완료 API가 사용하는 테이블과 정책
- 설문 문항 조회를 사용하는 경우 `survey_questions` 테이블 및 `track`, `stage`, `question_no` 컬럼

이 문서나 코드만으로 Supabase 테이블 또는 RLS 정책이 자동 생성되지는 않습니다.

## 9. 주의사항

- 실제 `.env`, 비밀번호, API 키, Supabase service role 키, 세션 비밀값은 업로드하지 마세요.
- `.venv`, `node_modules`, `__pycache__` 등 설치물/캐시 폴더는 업로드 대상이 아닙니다.
- 비회원 저장은 브라우저 로컬 저장소에 의존하므로 브라우저 데이터 삭제나 다른 기기에서는 복원되지 않을 수 있습니다.
- 화면에 추천 결과가 표시된 것과 서버 DB 저장이 완료된 것은 별개입니다. 저장 응답 또는 DB 데이터를 따로 확인하세요.
- 테스트를 실제 실행하지 않았다면 테스트 완료로 보고하지 마세요.
