## 1. 작업물 개요

이 폴더는 RecomEngine의 회원가입·로그인, 비회원/회원 상태 저장, 설문 진단 결과 저장, 시작 화면 및 이용 경험 선택 흐름 개선 작업물입니다.

- 작업 폴더: `새작업물/회원가입_비회원진단_데이터저장개선/`
- 기준 브랜치: `main`
- 2026-11-05 기능 업데이트 커밋: `a9c9baf`

이 폴더는 기존 프로젝트와 별도로 보관된 기능 작업물입니다. 프로젝트 전체를 대체하는 완성본으로 취급하지 말고, 기존 프로젝트의 동일 경로 파일과 비교해 적용하세요.

## 3. 개발 환경 준비

기존 RecomEngine 프로젝트 루트에서 작업합니다. 이 폴더만 단독으로 실행하는 프로젝트가 아닙니다.

### Python 백엔드

기존 프로젝트의 Python 버전과 의존성 관리 방식을 따르세요. 프로젝트 루트에 `requirements.txt`가 있는 경우:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

### 프론트엔드

기존 프로젝트에서 실제 `package.json`이 있는 프론트엔드 디렉터리로 이동한 뒤:

```powershell
npm install
```

설치 전 팀 프로젝트의 Node.js 버전 및 lock 파일 사용 기준을 확인하세요. 이 작업물 폴더에 별도 package manifest가 없다면 기존 프로젝트의 설정을 그대로 사용해야 합니다.

## 4. 환경변수 설정

1. `.env.example`에서 필요한 변수 이름을 확인합니다.
2. 기존 프로젝트가 읽는 환경변수 파일 위치와 설정 로더를 확인합니다.
3. 로컬 개발용 `.env`에 실제 값을 입력합니다.
4. 실제 비밀값이 든 `.env`는 Git에 추가하지 않습니다.

주요 설정:
- `USE_MOCK_DB`: 모의 DB 사용 여부
- `SUPABASE_URL`: Supabase 프로젝트 URL
- `SUPABASE_SERVICE_KEY`: 서버 측 DB 작업용 키
- `SUPABASE_ANON_KEY`: Supabase Auth 로그인 검증용 공개 anon 키
- `SESSION_SECRET`: RecomEngine 세션 쿠키 서명용 비밀값
- `SESSION_DAYS`: 세션 유지 일수
- `COOKIE_SECURE`: HTTPS 환경에서 secure 쿠키 사용 여부
- `OLLAMA_BASE_URL`, `OLLAMA_MODEL`: 로컬 Ollama 주소 및 모델
- `RAWG_API_KEY`, `IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET`, `STEAM_API_KEY`: 해당 외부 API를 사용할 때 설정

변수의 실제 필수 여부와 값은 현재 백엔드 설정 코드 및 배포 환경을 기준으로 판단하세요. 키를 임의로 생성하거나 다른 사람의 키를 문서에 붙여 넣지 마세요.

## 5. 주요 동작 확인

### 5.1 회원가입 및 로그인
- 시작 화면에서 회원가입을 선택합니다.
- 닉네임, 이메일, 비밀번호, 비밀번호 확인을 입력합니다.
- 비밀번호 확인이 일치하지 않으면 제출이 차단되는지 확인합니다.
- Supabase 이메일 인증이 필요한 설정이면 인증 메일 안내가 표시되는지 확인합니다.
- 이메일 인증 완료 후 회원가입을 마치고 이용 경험 선택 화면으로 이동하는지 확인합니다.
- 기존 계정 로그인은 메인 화면으로 이동하는지 확인합니다.

### 5.2 게스트 및 회원 상태 저장
- 비회원으로 진행해 이용 경험을 선택하고 빠른 진단을 시작합니다.
- 게스트 상태가 브라우저 로컬 저장소에 저장되는지 확인합니다.
- 게스트 데이터는 마지막 저장 시각 기준 7일 후 만료됩니다.
- 로그인 후 계정 상태가 불러와지고, 변경 내용이 서버 저장 큐를 통해 전송되는지 확인합니다.
- 저장 실패 상태가 표시되면 재시도/복구 흐름을 확인합니다.
- 로그아웃 전 마지막 상태가 저장되는지 확인합니다.

### 5.3 설문 진단 저장
- 빠른 설문 또는 완료 가능한 설문을 끝까지 진행합니다.
- 설문 완료 후 결과 화면이 먼저 표시되는지 확인합니다.
- 서버 연결이 가능한 환경에서는 진단 세션, 응답, 분석 결과 및 추천 결과 저장 요청이 실행되는지 확인합니다.
- 서버 저장에 실패해도 추천 결과 화면은 유지되고 안내 메시지가 표시되는지 확인합니다.
- 심화 설문 생성은 Ollama 연결 여부에 따라 AI 생성 또는 대체 문항 흐름으로 동작하는지 확인합니다.

## 6. 관련 API

### 계정
- `GET /api/account/session`
- `POST /api/account/signup`
- `POST /api/account/login`
- `POST /api/account/logout`
- `PUT /api/account/state`

### 설문
- `POST /api/survey/generate`: 28문항 blueprint를 바탕으로 심화 설문 생성
- `GET /api/survey/questions?track={track}&stage={stage}`: 트랙/단계별 설문 문항 조회

### 진단 저장
- `POST /api/sessions`: 진단 세션 생성
- `PUT /api/sessions/{session_id}/answers`: 답변 저장
- `POST /api/sessions/{session_id}/complete`: 분석 결과 및 추천 결과 저장

실제 사용 가능한 API와 요청 형식은 기존 백엔드 라우터 및 API 문서를 기준으로 확인하세요.

## 7. Supabase 확인 사항

기능을 실제 DB와 연결하려면 Supabase 프로젝트에서 다음을 확인해야 합니다.

- Auth 이메일 인증 활성화 여부 및 이메일 템플릿/리디렉션 설정
- `user_states` 테이블 존재 여부
- `user_states.user_id`의 유일성 및 upsert 가능 여부
- `user_states`의 RLS 정책과 서버 키 권한
- 진단 세션·응답·완료 API가 사용하는 테이블 및 정책
- 설문 문항 조회용 `survey_questions` 데이터와 컬럼

테이블이나 정책이 존재한다고 가정하지 말고 실제 프로젝트에서 확인하세요. 이 작업물 문서만으로 DB 마이그레이션이 수행되지는 않습니다.

## 8. 기존 프로젝트에 반영하는 방법

1. 저장소의 최신 `main`을 기준으로 작업합니다.
2. 기존 프로젝트에서 같은 경로의 파일과 이 작업물 파일을 비교합니다.
3. 팀원이 이미 수정한 내용이 있다면 최신 변경을 보존하고 충돌 부분을 검토합니다.
4. 백엔드와 프론트엔드의 API 요청/응답 형식, 인증 쿠키, 상태 구조가 서로 맞는지 확인합니다.
5. 필요한 코드만 반영하고 환경변수·테이블·RLS 설정을 별도로 점검합니다.
6. 로컬에서 회원가입, 로그인, 게스트 저장, 회원 저장, 설문 완료 및 서버 저장 실패 흐름을 테스트합니다.
7. 팀 저장소 반영은 팀의 GitHub 업로드 규칙에 따라 최신 `main`의 기존 작업 폴더를 갱신합니다. 별도 브랜치나 PR을 임의로 만들지 않습니다.

## 9. 주의사항

- 실제 `.env`, API 키, 세션 비밀값은 커밋하지 마세요.
- 게스트 저장은 해당 브라우저의 로컬 저장소에 의존합니다. 브라우저 데이터 삭제/기기 변경 시 사라질 수 있습니다.
- 회원 상태 서버 저장은 로그인 세션과 Supabase 테이블/권한 설정이 정상이어야 합니다.
- AI 설문 생성은 Ollama 연결 및 모델 준비 상태에 영향을 받습니다.
- 추천 결과 표시 성공과 서버 DB 저장 성공은 별개입니다. 저장 성공 안내 또는 DB 레코드를 별도로 확인하세요.
- 문서 업데이트 자체는 자동화 테스트나 운영 배포를 의미하지 않습니다.
