# 사용방법 및 기존 프로젝트 통합 안내

## 1. 작업물 개요

이 폴더는 회원가입·로그인, 설문 응답 및 추천 결과 저장, 게스트·회원 데이터 관리, 화면 흐름 개선 작업을 기존 프로젝트와 별도로 검토할 수 있도록 모아 둔 작업물입니다.

**독립 실행 가능한 전체 프로젝트가 아닙니다.** 기존 프로젝트의 전체 파일을 대체하지 말고, 아래 적용 절차에 따라 변경 파일을 검토한 뒤 통합하세요.

## 2. 폴더 및 파일 구성

작업물 폴더 안의 경로는 기존 프로젝트 루트를 기준으로 한 상대경로를 유지합니다.

### 변경된 파일 14개

**백엔드**
- `app/db.py`
- `app/routers/account.py`
- `app/routers/survey.py`
- `app/services/accounts.py`

**프론트엔드**
- `frontend/src/App.jsx`
- `frontend/src/components/common/DialogContents.jsx`
- `frontend/src/components/common/Modal.jsx`
- `frontend/src/components/layout/AppLayout.jsx`
- `frontend/src/hooks/profileActions.js`
- `frontend/src/hooks/surveyActions.js`
- `frontend/src/services/recommendationService.js`
- `frontend/src/state/AppContext.jsx`
- `frontend/src/utils/routes.js`
- `frontend/src/utils/storage.js`

**설정 및 문서**
- `.env.example`: 실제 비밀값이 없는 환경변수 예시
- `사용방법.md`: 설치·실행·테스트·통합 안내
- `변경내용_비교보고서.md`: 기능별 상세 변경 및 전체 요약

## 3. 개발 환경 및 의존성 설치

작업물 폴더만 따로 설치하는 방식이 아니라, 기존 프로젝트의 루트에서 개발 환경을 준비합니다.

### 백엔드

프로젝트 루트에서 실행합니다.

```bash
pip install -r requirements.txt
```

### 프론트엔드

`frontend` 폴더에서 실행합니다.

```bash
npm install
```

기존 프로젝트에 사용하는 Python 및 Node.js 버전과 패키지 관리 방식을 우선 따르세요. 별도 버전 지정 파일이 있다면 해당 파일의 기준을 사용합니다.

## 4. 환경변수 설정

이 폴더의 `.env.example`은 설정 항목을 확인하기 위한 예시입니다. 실제 서비스 키나 비밀번호는 포함되어 있지 않습니다.

1. 기존 프로젝트 루트의 환경변수 설정 방식을 확인합니다.
2. 예시 파일을 참고해 로컬 환경에 `.env`를 준비합니다.
3. 실제 Supabase 키, 세션 비밀값, 외부 API 키는 권한이 있는 담당자에게 안전한 방법으로 전달받아 로컬에만 입력합니다.
4. `.env` 파일은 Git에 추가하거나 공유하지 않습니다.

예시 파일에 정의된 환경변수 항목:
- 데이터베이스: `USE_MOCK_DB`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `SUPABASE_ANON_KEY`
- 세션 및 쿠키: `SESSION_SECRET`, `SESSION_DAYS`, `COOKIE_SECURE`
- 외부 게임·AI 연동: `RAWG_API_KEY`, `IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET`, `STEAM_API_KEY`, `ADMIN_TOKEN`
- 로컬 AI 설정: `OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `OLLAMA_TIMEOUT`, `OLLAMA_KEEP_ALIVE`, `OLLAMA_CONCURRENCY`
- 프론트엔드 접근 허용: `CORS_ORIGINS`

실제 연결에 필요한 값과 운영·개발 환경별 설정은 프로젝트 담당자가 확인하세요. 키 이름만으로 필수 여부나 권한 범위를 추측해 값을 임의 설정하지 마세요.

## 5. 실행 방법

### 프론트엔드

`frontend` 폴더에서 실행합니다.

```bash
npm run dev
```

### 백엔드

백엔드 실행 명령은 기존 프로젝트의 README 및 실행 설정을 따르세요. 이 작업물은 전체 백엔드 프로젝트가 아니므로, 이 폴더만을 기준으로 새 실행 진입점을 가정하지 않습니다.

프론트엔드와 백엔드를 함께 실행할 때는 기존 프로젝트에서 사용하던 포트, API 주소, CORS 설정을 확인하세요.

## 6. 테스트 및 확인

기존 프로젝트 루트와 `frontend` 폴더의 실제 테스트 스크립트를 먼저 확인한 뒤 실행하세요.

일반적으로 확인할 수 있는 명령은 다음과 같습니다. 프로젝트에 해당 스크립트나 테스트 설정이 존재하는지 확인한 후 사용하세요.

```bash
# frontend 폴더
npm test
npm run build

# 프로젝트 루트
pytest
```

주요 기능 확인 항목:
- 이메일 인증 전·후 회원가입 및 로그인 흐름
- 비밀번호와 비밀번호 확인 값 불일치 처리
- 게스트 상태의 저장 및 7일 만료 처리
- 회원 계정별 데이터 분리 및 로그아웃 처리
- 설문 응답 제출과 진단 결과 저장 흐름
- 추천 결과 표시 및 서버 저장 실패 시 화면 처리
- 비회원의 첫 7문항 완료 후 페이지 이동
- 이메일 인증 완료 화면과 모달 키보드 포커스 동작

**기존 작업자의 확인:** 업로드 전날 실행 및 기능 테스트를 진행했고 정상 작동했다고 보고했습니다. 이 문서는 해당 보고를 기록한 것이며, 이 안내문 업데이트 과정에서 테스트를 다시 실행했다는 의미는 아닙니다.

## 7. 기존 프로젝트에 적용하는 방법

이 작업물은 기존 프로젝트와 분리된 검토용 사본입니다. 아래 순서로 통합하세요.

1. 최신 `main` 또는 팀에서 지정한 통합 기준 브랜치를 가져옵니다.
2. 기존 프로젝트의 현재 파일을 백업하거나 별도 작업 브랜치에서 작업합니다.
3. 이 폴더의 14개 변경 파일을 열어 기존 프로젝트의 같은 상대경로 파일과 비교합니다.
4. 변경된 코드만 검토해 기존 프로젝트에 반영합니다. 기존 파일 전체를 무조건 덮어쓰지 말고, 팀원이 추가한 변경이 있다면 수동으로 병합합니다.
5. `.env.example`은 설정 항목 참고용입니다. 기존 `.env`나 팀의 환경 설정을 덮어쓰지 마세요.
6. 관련 팀원이 API 계약, 데이터 구조, 공통 상태관리 변경을 검토한 뒤 통합 브랜치에서 실행·테스트합니다.
7. 통합 결과가 확인되기 전에는 이 작업 브랜치를 `main`에 직접 병합하지 않습니다.

이 작업물은 `새작업물/회원가입_비회원진단_데이터저장개선/` 아래에 있으므로, 기존 프로젝트에 적용할 때는 해당 폴더 자체를 프로젝트 루트에 복사하는 것이 아니라 내부의 `app/` 및 `frontend/` 경로를 기준으로 파일을 비교·반영해야 합니다.

## 8. 통합 시 주의사항

- **계정/API 계약:** 회원가입·로그인 응답 형식과 인증 상태 처리 방식이 기존 백엔드 및 프론트엔드와 일치하는지 확인하세요.
- **Supabase 데이터 구조:** 실제 테이블, 컬럼, 제약조건 및 RLS 정책은 연결된 Supabase 프로젝트에서 확인하세요. 이 안내문은 스키마나 마이그레이션을 새로 생성하지 않습니다.
- **환경변수:** 기존 환경변수 이름과 배포 환경 설정을 확인하고, 비밀값을 코드나 Git 커밋에 포함하지 마세요.
- **상태관리 및 저장:** 게스트 데이터와 계정별 데이터의 저장 키, 복구, 로그아웃 동작이 다른 팀원의 변경과 충돌하지 않는지 확인하세요.
- **라우팅 및 UI:** 인증 콜백 경로, 설문 완료 경로, 모달 포커스 처리와 기존 라우터 구성을 함께 확인하세요.
- **의존성:** 기존 `requirements.txt` 및 `frontend/package.json`에 필요한 패키지가 있는지 확인하세요. 이 작업물의 변경 파일 목록에 포함되지 않은 의존성 파일은 임의로 교체하지 마세요.
- **통합 책임:** 최종 통합 전 코드 리뷰와 전체 회귀 테스트를 진행하세요.

## 9. 작업물의 범위

- 이 폴더는 기능 검토 및 통합을 위한 변경 파일 모음입니다.
- 기존 프로젝트에 자동으로 통합되거나 `main`에 병합된 상태가 아닙니다.
- 실제 Supabase 스키마 변경, 배포 설정 변경, 운영 환경 키 발급은 이 작업물에 포함되어 있다고 가정하지 마세요.
