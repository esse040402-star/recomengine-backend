## 2. 주요 기능

### 2.1 회원가입 및 로그인

관련 파일:
- `app/routers/account.py`
- `app/services/accounts.py`
- `frontend/src/hooks/profileActions.js`
- `frontend/src/state/AppContext.jsx`
- `frontend/src/components/common/DialogContents.jsx`

주요 동작:
1. 회원가입 시 닉네임, 이메일, 비밀번호를 입력하고 비밀번호 확인 값의 일치 여부를 프론트에서 검사합니다.
2. Supabase Auth를 이용해 계정을 생성하거나 기존 계정의 인증 상태를 확인합니다.
3. 이메일 인증이 필요한 경우 인증 메일 안내 상태를 반환하고, 인증 전에는 정상 로그인 세션을 만들지 않습니다.
4. 로그인 성공 시 서명된 HttpOnly 세션 쿠키를 발급합니다.
5. 로그인·회원가입 요청에는 시도 횟수 제한과 오류 메시지 처리가 포함됩니다.

### 2.2 회원별 상태 저장 및 복구

관련 파일:
- `app/routers/account.py`
- `frontend/src/state/AppContext.jsx`
- `frontend/src/utils/storage.js`
- 상태 저장 큐 관련 서비스 모듈

주요 동작:
1. 비회원 상태는 브라우저 로컬 저장소에 임시 저장하며 7일이 지나면 만료 처리합니다.
2. 로그인 사용자의 상태는 사용자 계정 ID별 로컬 저장 키로 분리합니다.
3. 서버 로그인 세션을 확인할 때 계정에 저장된 상태를 함께 불러옵니다.
4. 회원 상태 변경은 저장 큐를 통해 서버에 비동기 전송하고, 저장 실패 시 재시도할 수 있도록 임시 복구 데이터를 유지합니다.
5. 로그아웃 전 마지막 변경 상태를 저장하고 서버 세션을 종료하도록 처리합니다.

백엔드 계정 상태 API:
- `GET /api/account/session`: 현재 세션 및 저장 상태 조회
- `POST /api/account/signup`: 회원가입
- `POST /api/account/login`: 로그인
- `POST /api/account/logout`: 로그아웃
- `PUT /api/account/state`: 로그인 사용자 상태 저장

계정 상태 저장은 Supabase의 `user_states` 테이블을 사용합니다. 실제 DB에 해당 테이블과 정책이 준비되어 있는지 별도 확인이 필요합니다.

### 2.3 설문 진단 및 추천 결과 저장

관련 파일:
- `frontend/src/hooks/surveyActions.js`
- `frontend/src/services/recommendationService.js`
- `app/routers/survey.py`

주요 동작:
1. 빠른 설문, 심화 설문, 취향 설문 중 완료된 설문의 답변을 모읍니다.
2. 진단 세션을 생성한 뒤 응답을 세션에 연결해 저장합니다.
3. 분석 축, 취향 정보, 근거 및 추천 결과를 완료 API로 전달합니다.
4. 설문 완료 후 화면 이동을 먼저 진행하고 저장은 백그라운드에서 처리합니다.
5. 저장 실패 시 추천 화면은 유지하고 사용자에게 서버 저장 실패 안내를 표시합니다.
6. 심화 설문 생성은 28개 blueprint 문항을 기준으로 Ollama에 요청하며, AI 요청 실패 시 프론트의 대체 문항으로 진행할 수 있습니다.
7. `GET /api/survey/questions`는 트랙과 단계에 맞는 `survey_questions` 데이터를 조회합니다.

진단 저장 API 호출 흐름:
- `POST /api/sessions`: 진단 세션 생성
- `PUT /api/sessions/{session_id}/answers`: 설문 응답 저장
- `POST /api/sessions/{session_id}/complete`: 분석 결과 및 추천 데이터 저장

## 4. 환경변수

루트의 `.env.example`에는 설정 항목 이름과 로컬 개발 기본값만 기록합니다. 실제 비밀값은 포함하지 않습니다.

주요 항목:
- Supabase: `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `SUPABASE_ANON_KEY`
- 세션: `SESSION_SECRET`, `SESSION_DAYS`, `COOKIE_SECURE`
- 게임 API: `RAWG_API_KEY`, `IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET`, `STEAM_API_KEY`
- Ollama: `OLLAMA_BASE_URL`, `OLLAMA_MODEL`, `OLLAMA_TIMEOUT`, `OLLAMA_KEEP_ALIVE`, `OLLAMA_CONCURRENCY`
- 기타: `USE_MOCK_DB`, `ADMIN_TOKEN`, `CORS_ORIGINS`

실제 운영 환경에서 필요한 값은 프로젝트 설정과 배포 환경을 확인해 입력해야 합니다. `.env` 파일이나 실제 키는 저장소에 커밋하지 마세요.
