# 기존 모듈 연결

## Python
```python
from personal import PersonalStore
store = PersonalStore('data/personal.sqlite3', catalog=game_catalog)
```
`game_catalog`는 기존 API 계층의 게임 목록이며 각 항목에 `id`(프론트 내부 ID), `app`(Steam AppID), `title`이 필요합니다. 테스트 fixture를 실제 게임정보로 사용하지 마세요.

기존 웹 프레임워크에서 다음 경로를 연결합니다. owner는 요청 본문의 값이 아니라 검증된 로그인 세션 사용자 ID 또는 서버가 관리하는 게스트 ID를 사용합니다. 기존 인증/CSRF 검사를 유지하세요.

| 경로 | 연결 |
|---|---|
| GET /api/personal | store.state(owner) |
| POST /api/personal/settings | store.update(owner, 'settings', body) |
| POST /api/personal/wishlist | store.update(owner, 'wishlist', body) |
| POST /api/personal/recent | store.update(owner, 'recent', body) |
| POST /api/personal/profiles | store.update(owner, 'profiles', body) |
| POST /api/personal/active | store.update(owner, 'active', body) |

성공 응답은 JSON으로 반환합니다. ValueError는 422와 `{ "detail": "오류 내용" }`로 반환합니다. GET/POST를 브라우저와 같은 출처로 제공하세요.

설문 백엔드가 확정한 결과(클라이언트가 임의 전송한 점수 사용 금지)를 저장한 직후:
```python
store.record_survey(owner, result)
# result: result_id, summary(title/count/evidence), weights 필수
# 제출 재시도 시 동일 survey의 프로필이 있으면 재생성하지 않습니다.
if not any(p['survey'] == result['result_id'] for p in store.state(owner)['profiles']):
    store.update(owner, 'profiles', {'name': result['summary']['title'][:30], 'survey': result['result_id']})
```
회원가입 시 게스트 데이터 이전은 기존 계정 모듈에서 accounts/activity/surveys/profiles의 owner를 트랜잭션으로 이전하세요. 기존 사용자 계정과 합칠 때는 충돌 처리 정책이 필요합니다. 이 모듈은 인증을 구현하지 않습니다.

## 원본 HTML
personal.js는 독립 앱이나 React 컴포넌트가 아닙니다. 기존 `화면_최종.html`의 공통 스크립트 내부에서 동일 이름 함수를 교체해 사용합니다. 중복 함수나 let personalData를 남기지 마세요. 원본의 state, save, render, game, card, savedGames, accountSettings, profileSettings, report, btn, icon, esc, openDialog, closeDialog, beginServerQuick, $, $$와 dialogDraft/profileTab/route를 사용합니다.

1. 기존 activityPanel을 originalActivityPanel로 이름 변경하고, personal.js의 함수들을 연결합니다.
2. personal.css를 원래 CSS 다음에 추가합니다. 원본 profile-cover/게임 카드/팝업 디자인을 유지합니다.
3. profileTab 초기값은 history. 기존 profile-tab 클릭 처리를 유지합니다.
4. 개인페이지 진입과 로그인 완료 시 loadPersonal() 호출. 7문항 제출 성공 후 await personalRequest('') 호출.
5. 기존 detail(id)의 게임 검증 다음에 `personalRequest('recent',{game:id}).catch(e=>toast(e.message))` 추가.
6. 기존 save 버튼은 이 파일의 saveGame(id)를 호출합니다.
7. 설정의 '게임 포인트 색상/customize' 행을 '프로필 꾸미기/edit-profile'로 변경합니다. 설정 저장 확인 버튼은 personal-inspect 액션으로 연결합니다.
8. 기존 profile-banner 처리에서 dialogDraft.banner를 변경하고 #cover-preview의 backgroundImage를 profileCoverImage(id)로 갱신합니다.
9. 기존 input 이벤트에서 cover_y는 dialogDraft.cover_y와 미리보기 backgroundPosition을 갱신하고, cover_shade는 dialogDraft.cover_shade와 미리보기 boxShadow(값/500 불투명도)를 갱신합니다.
10. 제공된 캡처 단계 이벤트 핸들러가 개인페이지 저장/프로필 액션만 처리합니다. 로그인·게임 탐색·설문 이벤트는 기존 코드가 처리합니다.

카드 이미지는 Steam library_hero를 우선 사용하고 원본 게임 이미지로 대체합니다. object-fit:cover로 비율을 유지하며 카드 바깥 부분만 자릅니다. 흐려지는 가장자리 그라데이션은 없습니다.
