# 설문 선택지 매핑 최종 검토

검토일: 2026-11-17  
기준: 기존 `recomengine_update_03_supabase_synced.zip`  
원칙: 설문 질문·선택지 문구와 순서는 유지하고, 선택지 해석 및 추천 반영 코드와 검증만 보완

## 1. 전체 결과

전체 366개 선택지를 실행 가능한 설문 엔진(`quickQuestions`, `profileQuestions`) 기준으로 분류했다. 게이머/비게이머 각각 빠른 설문과 프로필 설문을 합산한 수치다.

| 분류 | 개수 | 처리 |
|---|---:|---|
| 취향 축 점수 부여 | 240 | 6개 취향 축에 반영 |
| 점수 없이 명시적 메타데이터로 처리 | 72 | 플랫폼, 회피 조건, 장르, 시점, 소셜, 시간, 사운드, 집중 방식 등으로 보존 |
| 중립·불확실 또는 축 중립값 | 54 | 임의 점수를 만들지 않음 |
| 합계 | 366 | 전체 선택지 검사 |

점수가 없는 선택지가 곧 누락 오류인 것은 아니다. 예를 들어 '상관없어요', '잘 모르겠어요', '상황에 따라 달라요'는 중립 응답으로 유지한다. 플랫폼과 회피 요소는 취향 축 점수 대신 필터 조건으로 처리한다.

숫자 점수는 설문 의미가 명확한 선택지에만 추가했다. '상황에 따라', '잘 모르겠음', '특별히 선호 없음' 같은 응답에는 임의 점수를 부여하지 않았다.

## 3. 실제 추천 반영 테스트

신규 `preferenceEngine.mapping.test.js`는 다음을 확인한다.

1. 게이머·비게이머의 빠른 설문과 프로필 설문 전체 366개 선택지가 진단 근거(evidence)에 전달되는지
2. 점수 있는 선택지는 축 계산에 반영되는지
3. 점수가 없는 선택지는 명시적 메타데이터로 보존되거나 중립 응답으로 분류되는지
4. 중립 응답이 임의 취향 점수를 만들지 않는지
5. PC 플랫폼 선택과 과금 회피 조건이 추천 후보 필터에 실제 적용되는지
6. 새로 보완한 숙련·전투·탐색·자동 진행·학습 방식 신호가 추천 적합도(metadataAdjustment)에 반영되는지

## 4. 검증 결과

- 프론트엔드 Node 테스트: **14개 통과** (`node --test frontend/tests/*.test.js`)
- 프론트엔드 주요 JS 구문 검사: **통과** (`node --check`)
- 백엔드 테스트: **102개 통과** (`python -m pytest -q`)
- Vite production build: **미완료**. `npm run build`를 실행했으나 `vite: not found`로 종료됐다. 압축본에 `frontend/node_modules`가 없고, 현재 실행 환경 Node.js는 `v22.16.0`으로 프로젝트 엔진 요구사항 `^22.18.0 || >=24.11.0`보다 낮다. 앞선 설치 시도에서는 npm registry DNS 조회도 실패했으므로 Vite 컴파일 성공 여부는 아직 확인할 수 없다.

## 5. 변경하지 않은 항목

- 설문 질문 및 선택지 문구/순서
- Supabase 운영 DB 및 마이그레이션 적용 상태
- `.env` 및 인증 정보
- 게임 카탈로그 원본

주의: 카탈로그에 개별 태그가 없는 사운드, 세계관, 시각 접근성 등의 메타데이터는 응답 분석 정보로 보존되지만, 카탈로그 태그가 추가되기 전까지 모든 항목이 독립적인 게임 필터/랭킹 기준이 되는 것은 아니다. 이를 점수화했다고 과장하지 않았다.
